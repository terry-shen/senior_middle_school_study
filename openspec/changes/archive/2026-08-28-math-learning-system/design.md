## Context

当前项目为全新构建的高中数理化辅助学习系统，首期聚焦数学学科。需要构建一个支持Web端访问的全栈应用，包含前端界面、后端API服务、数据库存储以及OCR/文档解析等外部依赖。系统需要处理试题的智能分析、知识点匹配和自动出卷等复杂业务逻辑。

## Goals / Non-Goals

**Goals:**
- 构建可扩展的Web应用架构，支持PC端和移动端浏览器访问
- 实现高效的试题解析、知识点匹配和逐题拆分
- 提供直观的用户界面用于知识点管理、试卷操作和在线测验
- 确保系统响应速度满足实时交互需求
- 构建灵活的大模型集成架构，支持本地和云端模型的无缝切换
- 实现完整的在线测验流程（选择题在线答题、其他题型拍照上传）
- 实现AI自动批改功能，支持所有题型
- 实现知识点掌握度评估，基于答题正确率自动打分

**Non-Goals:**
- 不实现移动端原生应用（Web响应式设计即可）
- 不自行训练或微调大模型（使用现成模型）
- 不实现多学科（物理/化学）的支持（后续扩展）
- 不实现在线视频教学功能
- 不实现社交功能（讨论区、评论等）

## Decisions

### 技术栈选择
**决策**: 采用 React + TypeScript 前端，Node.js + Express 后端，PostgreSQL 数据库

**理由**:
- React 生态成熟，组件化开发效率高
- TypeScript 提供类型安全，减少运行时错误
- Node.js 与前端技术栈统一，开发效率高
- PostgreSQL 支持复杂查询和JSON数据类型，适合知识点图谱存储

**备选方案**:
- Vue.js + Python/Django: Vue学习曲线平缓但生态略逊，Python适合AI但前后端分离不够彻底
- MongoDB: 灵活但不适合复杂关联查询

### 知识点数据模型
**决策**: 采用邻接表模型存储知识点层级关系，配合物化路径优化查询

**理由**:
- 邻接表易于维护层级关系
- 物化路径字段支持快速查询祖先/后代节点
- 结合PostgreSQL的递归查询支持复杂知识图谱遍历

**备选方案**:
- 纯嵌套集合: 查询快但插入更新复杂
- 图数据库(Neo4j): 过度工程化，增加运维复杂度

### 试卷解析策略
**决策**: 采用混合解析策略，PDF使用pdf-lib解析，图片使用Tesseract OCR

**理由**:
- pdf-lib纯JavaScript实现，无需外部依赖
- Tesseract开源免费，支持中文识别
- 混合策略覆盖主流格式，平衡准确性和成本

**备选方案**:
- 商用OCR API: 成本高，依赖外部服务
- 单一格式支持: 用户体验差

### 自动出卷算法
**决策**: 采用贪心算法结合约束满足问题(CSP)求解

**理由**:
- 贪心算法快速生成初始解
- CSP求解优化知识点覆盖和难度分布
- 平衡生成速度和解质量

**备选方案**:
- 纯遗传算法: 收敛慢，实时性差
- 纯随机抽样: 难以保证约束满足

### 大模型集成架构
**决策**: 构建统一的模型适配层，支持Ollama本地部署和云端API的统一调用

**理由**:
- Ollama支持本地部署开源模型（Qwen、DeepSeek、Llama等），无需联网，数据隐私有保障
- 云端API提供更强的模型能力，适合高精度需求场景
- 统一适配层屏蔽不同模型接口差异，支持热切换和降级策略
- 适配层支持Prompt模板管理，优化不同任务（解析生成、答案生成、难度评估）的提示词

**推荐模型配置**:
- **本地部署（Ollama）**:
  - Qwen2.5:7B/14B - 中文数学能力优秀，资源消耗适中
  - DeepSeek-Coder:6.7B - 代码和数学推理能力强
  - Llama3.1:8B - 英文能力强，多语言支持好
- **云端API**:
  - 智谱AI GLM-4 - 中文能力顶尖，数学推理准确
  - 阿里云Qwen-Max - 性价比高，适合大规模使用
  - OpenAI GPT-4o - 综合能力最强，但成本较高

**备选方案**:
- LangChain框架: 过度封装，增加学习成本和调试难度
- 直接硬编码单个模型: 缺乏灵活性，无法适应不同部署环境

### Prompt工程策略
**决策**: 采用结构化Prompt模板库，针对不同AI任务优化提示词

**理由**:
- 不同任务（知识点识别、解析生成、答案生成、难度评估）需要不同的Prompt结构
- 模板库支持版本管理和A/B测试，持续优化AI输出质量
- 支持注入知识点体系上下文，提高AI匹配准确性

**模板示例**:
```
# 知识点识别Prompt
角色：高中数学教师
任务：分析试题涉及的知识点
输入：试题内容 + 知识点体系
输出：JSON格式 {knowledge_points: [{name, weight, confidence}]}
```

**备选方案**:
- 单一通用Prompt: 难以针对不同任务优化
- 无模板管理: 维护困难，优化迭代不可控

### 学生管理与认证架构
**决策**: 采用JWT Token认证，角色分为学生和管理员两类

**理由**:
- JWT无状态认证适合分布式部署，无需服务端Session存储
- 学生和管理员权限分离，简化权限模型
- 学生账号支持学号+密码登录，符合学校使用习惯

**数据库设计**:
- students表：id, student_id(学号), name, password_hash, class_id, created_at
- classes表：id, name, grade, created_at
- tokens表：id, student_id, token, expires_at

**备选方案**:
- OAuth2认证: 复杂度高，学校场景下过度设计
- Session认证: 需要服务端存储，不利于横向扩展

### 在线测验架构
**决策**: 选择题使用实时保存策略，填空题/解答题采用图片上传+OCR流程

**理由**:
- 选择题答案简单，实时保存到数据库，支持中断恢复
- 填空题/解答题需要手写，拍照上传是最自然的交互方式
- OCR识别后展示给学生确认，提高准确性

**答题记录数据模型**:
- exam_records表：id, student_id, exam_id, status, started_at, submitted_at
- answer_records表：id, exam_record_id, question_id, answer_type(online/photo), answer_content, answer_image_url, graded, score

**备选方案**:
- 全题型在线输入: 手写输入体验差，不适合数学公式
- 全题型拍照上传: 选择题无需手写，增加不必要步骤

### AI批改Prompt设计
**决策**: 针对不同题型设计专用批改Prompt模板

**理由**:
- 选择题批改简单，对比标准答案即可
- 填空题需要识别等价答案，如"√2"和"根号2"
- 解答题需要分析解题步骤，按评分标准打分

**Prompt模板设计**:
```
# 解答题批改Prompt
角色：高中数学教师
任务：批改学生的解答题答案
输入：
  - 题目内容
  - 标准答案和评分标准
  - 学生答案（OCR识别后的文本或原图片）
输出：JSON格式 {
  score: 总分,
  steps: [{content: 步骤描述, score: 该步得分, correct: true/false}],
  comment: 批改评语
}
```

**备选方案**:
- 统一Prompt模板: 难以针对不同题型优化
- 纯规则批改: 无法处理灵活的表述差异

### 掌握度计算模型
**决策**: 采用加权正确率计算知识点掌握度

**公式**:
```
掌握度 = Σ(试题得分 × 难度权重) / Σ(试题满分 × 难度权重) × 100
难度权重：简单=0.8, 中等=1.0, 较难=1.2, 困难=1.5
```

**理由**:
- 加权计算体现不同难度试题的区分度
- 高难度题目答对对掌握度贡献更大
- 权重可配置，适应不同教学需求

**备选方案**:
- 简单平均正确率: 忽略难度差异，评价不精准
- 贝叶斯知识追踪(BKT): 复杂度高，需要大量数据校准

### 错题本数据模型
**决策**: 采用独立错题表设计，与答题记录表分离

**理由**:
- 错题本需要独立的复习状态管理（未复习/正在攻克/已理解/已掌握）
- 支持错题重练记录追踪，不污染原答题记录
- 便于错题的多维度检索和统计

**数据库设计**:
```
wrong_questions表：
- id, student_id, question_id, exam_record_id
- error_count（错误次数）
- first_error_at, last_error_at
- review_status（复习状态）
- last_review_at
- mastery_status（掌握状态）
```

**备选方案**:
- 从答题记录表动态查询错题: 查询效率低，无法管理复习状态
- 在答题记录表添加错题标记: 混杂业务逻辑，难以扩展

### 个性化推荐算法
**决策**: 采用基于知识点掌握度的混合推荐策略

**算法逻辑**:
```
推荐得分 = α × (1 - 知识点掌握度) + β × 错题权重 + γ × 知识点依赖权重
其中 α=0.5, β=0.3, γ=0.2
```

**理由**:
- 优先推荐掌握度低的知识点（最近发展区原则）
- 结合错题情况，重点攻克高频错误知识点
- 考虑知识点前置依赖，按合理顺序学习

**备选方案**:
- 协同过滤推荐: 新用户冷启动问题严重，数据量不足
- 纯规则推荐: 缺乏个性化，无法适应不同学生

### 知识地图可视化技术
**决策**: 前端采用D3.js库渲染树形图和地图，支持交互操作

**理由**:
- D3.js是成熟的数据可视化库，支持复杂的树形图和力导向图
- 支持丰富的交互操作（缩放、拖拽、点击、悬停）
- 性能优化好，可渲染大规模节点

**备选方案**:
- ECharts: 树形图功能较弱，自定义程度低
- Canvas直接绘制: 开发成本高，交互实现复杂

### 模拟考试架构
**决策**: 前端使用倒计时定时器，后端记录考试时长并支持自动提交

**理由**:
- 前端倒计时实时性好，用户体验佳
- 后端记录防止前端篡改时间
- 支持断网后恢复考试进度

**数据模型**:
```
mock_exams表：
- id, student_id, exam_paper_id, status
- started_at, submitted_at, time_limit
- total_score, graded_at

mock_exam_answers表：
- id, mock_exam_id, question_id
- answer_content, answer_image_url
- is_marked（标记待检查）, score
```

**备选方案**:
- 纯后端倒计时: 需要频繁请求服务器，实时性差
- 不支持中断恢复: 用户误关闭页面后无法继续考试

### 学习激励数据模型
**决策**: 采用独立的徽章表和打卡记录表，与用户表关联

**理由**:
- 徽章和打卡记录是独立的业务实体，便于管理
- 支持徽章的灵活扩展，不修改用户表结构
- 便于统计和查询学生的激励数据

**数据库设计**:
```
badges表：
- id, name, description, icon_url
- condition_type, condition_value（达成条件）
- rarity（稀有度）

user_badges表：
- id, student_id, badge_id, earned_at

check_ins表：
- id, student_id, check_in_date
- streak_count（连续打卡天数）
```

**备选方案**:
- 在用户表中存储激励数据: 字段膨胀，难以扩展
- 使用NoSQL存储: 关系型查询复杂，PostgreSQL足够

### 管理员后台架构
**决策**: 前端采用独立的管理后台应用，与学生前端分离，共享后端API

**理由**:
- 管理员界面功能与学生界面差异大，独立开发更灵活
- 权限控制更清晰，管理员界面需要严格的权限验证
- 便于独立部署和访问控制（可限制管理后台只能内网访问）

**数据库设计**:
```
admin_users表：
- id, username, password_hash, name, role
- permissions（JSON数组存储权限列表）
- created_at, last_login_at

admin_audit_logs表：
- id, admin_id, action, target_type, target_id
- details（JSON存储操作详情）
- ip_address, created_at
```

**备选方案**:
- 前端路由分离: 共用一个前端应用，通过路由区分，但权限控制复杂
- 完全独立后端: 增加运维复杂度，数据共享困难

### 知识点导入与融合架构
**决策**: 采用AI解析+人工确认的混合策略，冲突由管理员决策

**理由**:
- AI自动解析PDF/图片效率高，但准确率不稳定
- 知识点冲突处理需要专业判断，不能完全自动化
- 保留管理员决策权，确保知识点体系质量

**导入流程**:
```
1. 上传文件 → AI解析知识点结构
2. 检测重复和冲突 → 生成冲突报告
3. 展示预览界面 → 管理员审核和决策
4. 执行导入/融合 → 更新知识点体系和关联关系
5. 记录导入历史 → 支持回滚
```

**冲突检测逻辑**:
- 名称相似度检测（编辑距离算法）
- 描述内容比对
- 层级路径匹配
- 知识点ID映射检查

**备选方案**:
- 完全自动融合: 可能引入错误，破坏知识点体系
- 完全手动导入: 效率低，无法批量处理

### 学生反馈处理流程
**决策**: 反馈+临时标注机制，不影响其他学生正常使用

**理由**:
- 学生反馈需要及时响应，但不应干扰正常学习
- 临时标注提醒其他学生注意，提高透明度
- 管理员审核确保反馈质量，避免误报

**反馈处理流程**:
```
1. 学生提交反馈 → 创建反馈记录
2. 题目标注"待审核" → 其他学生看到提示
3. 管理员审核反馈 → 验证问题真实性
4. 采纳反馈 → 修正题目，更新关联，重新批改（可选）
5. 驳回反馈 → 移除标注，通知学生
6. 反馈数据汇总 → 用于题目质量评估和AI训练
```

**数据库设计**:
```
question_feedbacks表：
- id, student_id, question_id, feedback_type
- description, status（待审核/已采纳/已驳回）
- admin_comment, created_at, processed_at

question_labels表：
- id, question_id, label_type, label_text
- created_at, expires_at（可选过期时间）
```

**备选方案**:
- 反馈即下线: 影响题库可用性，可能被恶意利用
- 反馈无标注: 其他学生无法获知题目问题，降低信任度

### 几何图形标注技术
**决策**: 前端使用Canvas实现标注工具，后端存储标注数据为JSON

**理由**:
- Canvas绘图性能好，适合交互式标注
- JSON格式便于存储、传输和AI处理
- 支持触摸设备，移动端体验好

**标注数据格式**:
```json
{
  "imageId": "geometry_123",
  "annotations": [
    {"type": "point", "x": 100, "y": 150, "label": "A", "color": "#000000"},
    {"type": "line", "x1": 100, "y1": 150, "x2": 200, "y2": 150, "style": "solid", "color": "#000000"},
    {"type": "angle", "center": {"x": 150, "y": 150}, "radius": 20, "start": 0, "end": 90, "color": "#FF0000"},
    {"type": "text", "x": 150, "y": 160, "content": "AB=5", "fontSize": 14}
  ]
}
```

**前端实现技术**:
- Canvas API绑绘图和事件处理
- 支持撤销/重做栈
- 支持触摸手势（缩放、平移）
- 导出为PNG图片或JSON数据

**备选方案**:
- SVG实现: 交互性稍差，适合静态图形
- 第三方标注库: 增加依赖，定制性受限

## Risks / Trade-offs

[OCR识别准确率] → 提供手动修正功能，建立人工标注数据集用于后续模型优化

[知识点匹配算法准确率] → 设置置信度阈值，低置信度结果标记为待审核

[大模型输出质量不稳定] → 采用结构化Prompt模板，实现输出验证机制，低质量结果标记为待审核

[AI批改准确性] → 实现人工审核机制，记录修正数据用于Prompt优化，设置低置信度结果标记为待审核

[填空题/解答题OCR识别] → 识别结果展示给学生确认，支持手动修正，提高批改输入准确性

[本地模型资源消耗] → 提供模型资源需求评估工具，推荐适配不同硬件配置的模型选择

[云端API成本控制] → 实现Token使用量监控和预算预警，支持自动切换到本地模型降级

[模型调用延迟] → 实现异步处理和进度反馈，关键场景支持流式输出

[系统性能] → 实现异步处理和进度反馈，避免长时间阻塞用户操作

[数据一致性] → 采用事务处理关键操作，实现乐观锁防止并发冲突

[答题数据安全] → 敏感信息加密存储，HTTPS传输，学生数据访问权限严格控制

[移动端适配] → 前端采用响应式设计，拍照上传功能支持移动端浏览器

[错题本数据量增长] → 实现错题归档功能，超过6个月的已掌握错题自动归档，支持手动清理

[推荐算法冷启动] → 新学生首次登录时，基于知识点难度从易到难推荐，积累数据后启用个性化推荐

[知识地图渲染性能] → 大规模知识点树采用懒加载和虚拟滚动，节点超过500时启用搜索定位

[模拟考试作弊防范] → 前端记录切屏次数并上报，后端检测异常答题速度，提醒教师关注

[激励系统过度游戏化] → 控制徽章和排行权重，核心功能围绕学习效果，激励为辅

[错题重练效果追踪] → 记录重练结果和掌握度变化，分析错题重练对掌握度提升的贡献度

[学习路径合理性问题] → 引入知识点依赖关系，确保前置知识点掌握后再推荐后续知识点

[知识点导入冲突处理] → 提供详细的冲突报告和多种解决选项，记录融合历史支持回滚

[管理员权限滥用] → 实现操作审计日志，关键操作需二次确认，支持权限分级

[学生反馈恶意利用] → 限制单个学生每日反馈次数，管理员可标记恶意反馈并禁言

[几何图形标注数据量大] → 采用增量存储策略，定期归档历史标注，优化存储格式

[几何标注工具性能] → 使用Canvas离屏渲染优化，限制最大标注数量，支持懒加载
