## Context

「AI 助理」不是站内对话功能，而是管理员维护的外部站点目录：`AiAssistant` 保存名称、网址、图标与启用状态，学生点击后在新窗口打开对方官网。当前任何登录学生都能看到 `/ai-assistants` 入口并调用 `GET /api/ai-assistants`，没有按学生控制的字段。

账号体系只有 `student` / `admin` 两种角色；`requireAuth` 已通过 `include: { student: true }` 拿到完整学生记录，但只把 `id / studentId / name / role` 映射到 `req.user`。学生列表已有搜索和单个编辑能力，适合承载逐人开关。

## Goals / Non-Goals

**Goals:**

- 学生级 `aiAssistantEnabled` 开关，默认关闭，管理员逐个开放
- 未授权学生看不到导航入口，页面与接口双层拦截
- 注册接口强制 `student` 角色，堵住自封管理员的提权路径
- 授权变更在下一次接口请求立即生效，无需强制注销会话

**Non-Goals:**

- 不做使用时长、打开次数、交互记录或统计看板
- 不做班级批量授权、按助理站点的权限矩阵
- 不修改 APK、不做网络层封锁
- 不阻止学生直接访问外部 AI 官网

## Decisions

### 用学生表布尔字段，不建独立授权表

`Student.aiAssistantEnabled Boolean @default(false)` 足够表达“开/关”，不需要授权历史、有效期或审批流。独立授权表会增加 join、迁移和页面复杂度，当前需求没有这些收益。后续若需要临时授权或审批，再升级为授权表。

### 管理端使用独立的管理员接口

新增 `PATCH /api/students/:id/ai-access`，只挂 `requireAuth + requireAdmin`。不复用现有 `PUT /api/students/:id`，因为该接口允许学生修改自己的资料，混入授权字段会导致学生给自己开权限。

### 权限判定以服务端为准，前端只负责呈现

登录/注册响应和 `GET /api/auth/me` 返回 `aiAssistantEnabled`，前端据此隐藏侧边栏入口和页面；`GET /api/ai-assistants` 在服务端再判一次，未授权学生返回 403。这样即使前端判断被绕过，也拿不到站点数据。管理员在两层都放行。

### 注册角色在路由与服务两层固定

`routes/auth.ts` 不再把请求体 `role` 传下去，`auth-service.registerStudent` 也固定写入 `student`。两层都改是为了防止以后新增调用方绕过路由层。管理员创建账号仍走 `POST /api/students`，该接口本来就只允许管理员。

### 直接访问未授权页面时展示提示

`/ai-assistants` 在未授权时显示“该功能未开放”并给出返回工作台的链接，而不是静默重定向。这样学生知道是权限问题，不会误以为页面损坏；导航项本身仍然不显示。

### 授权变更不强制注销会话

`requireAuth` 每次请求都会重新读取学生记录，接口层没有缓存，因此关闭授权后下一次 AI 助理请求立即 403。前端导航在刷新或重新登录后更新；不为了一个入口去批量删会话。

## Risks / Trade-offs

- **学生绕过站内入口**：知道豆包/DeepSeek 网址仍可直接访问 → 明确这是入口控制，不是网络封锁；如需真阻断，后续再评估网络层或设备管控。
- **导航更新有延迟**：已登录学生的侧边栏要刷新才消失 → 接受；接口已即时 403，不影响实际权限。
- **默认关闭造成开通工作量**：上线后管理员需要逐个开 → 学生列表已有搜索，按学号/姓名定位；不做班级批量是本次明确取舍。
- **自助注册仍然开放**：学生仍可注册新账号 → 新账号默认关闭，不会自动获得 AI 助理；管理员账号不能再通过注册接口创建。
- **历史/导入学生**：批量导入服务创建的学生没有显式字段 → 依赖数据库默认 `false`，需在验证中确认导入后仍为关闭。

## Migration Plan

1. `backend/prisma/schema.prisma` 增加字段，执行 `npx prisma db push` 与 `npx prisma generate`；SQLite 会为存量行填充默认值 `false`。
2. 后端先发布：注册角色固定、登录态字段、授权接口、列表接口 403。
3. 前端随后发布：类型、侧边栏判断、页面提示、学生列表开关。
4. 回滚：前端回滚后入口恢复显示但接口仍会 403；如需完全回滚，后端回滚代码即可，数据库多出的列可保留，不影响旧代码。
