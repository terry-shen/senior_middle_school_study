## Context

参见 `proposal.md - Why`。这里只记录影响实现方式的现状与约束。

**现有资产（不要重写）**

| 资产 | 规模 | 关键约束 |
|---|---|---|
| 网盘接入 | ~438 行（`netdisk-service` + `netdisk` 路由） | OAuth 授权码模式；`refresh_token` 链式单次有效，必须先存新值再用；dlink 必须追加 `&access_token=`；流代理需透传 Range 并返回 206；仅能访问 `/apps/{appname}` |
| MinerU 解析 | ~780 行（`mineru-service` + `papers` 导入分支） | 常驻 `mineru-api`（CLI 临时 API 会 502）；Word 必须先经 Word COM 转 PDF（MathType MTEF 无法直接转 OMML）；图片为 data URI 需剥前缀 |
| 答题纸批改 | ~700 行（`answer-sheets` + Canvas 组件） | 图片走 Canvas 矩形/文字/画笔/撤销；Word 走下载→本地批注→回传批改版；学生只读查看时叠加批注层 |
| 数据 | SQLite 单文件 | 27 张表、13k 外部资源、284 份整卷试卷；不支持在线 DDL 并发 |

**新增约束**

- 学科先只启用数学；教材版本先只做人教 A。
- 13k 文件不落本地，全部通过网盘实时访问。
- 学生第一用户；练习环节沿用现有方案（整卷 + 答题纸），不做逐题在线作答。
- 视频不打时间戳，只做索引。

## Goals / Non-Goals

**Goals:**

- 学生能用「册 → 章 → 节」三步到达任意一份学习资源，且每节默认视图不超过 5 条精选。
- 网盘 13k 资源可被检索、可被映射、可被人工校正，且全流程零文件迁移。
- 试卷、视频、错题三类数据都能挂到同一个 Section 坐标上。
- v1 的三大高价值资产（网盘、MinerU、答题纸）以"复制而非重写"的方式进入 v2。

**Non-Goals:**

- 不做多教材版本并行（人教 B / 北师大）——只保留 `edition` 字段预留。
- 不做视频时间戳/章节切片/字幕对齐。
- 不做资源文件本地缓存或转码。
- 不在 v2 恢复知识点树、掌握度、个性化推荐、知识地图。
- 不做在线逐题测验的教学化改造（直接下掉）。

## Decisions

### D1 在同一仓库开 `v2` 分支重写，而不是新仓库

**选择**：`main` 打 tag `v1-final` 后冻结，新建 `v2` 分支做结构性重写，复用同一 git 历史、同一 OpenSpec 归档、同一个 `dev.db`。

**理由**：约 65% 代码（后端保留 35%、前端保留 50%）仍要用，且留下的是最难写的三块；OpenSpec 的 24 个主 spec 与 18 次归档是重要的决策史料；同一数据库意味着零数据迁移，v1 的 284 份试卷与 13k 索引可被 v2 直接复用。

**替代方案**：新仓库重写——被否，理由是资产搬迁成本高、历史丢失、需要数据导出/导入两套脚本。

### D2 章节轴用 3 张表，Section 是唯一可挂载粒度

**选择**：`Textbook(subjectId, name, edition, grade, order)` / `Chapter(textbookId, order, title)` / `Section(chapterId, order, title)`；所有业务外键只指向 `Section`。

**理由**：册和章是导航用的中间层，真正与资源一一对应的是节（人教 A 共约 90 节，正好是"每节 3-5 个精选"的合适粒度）。若只做 Chapter，一节 200+ 资源无法收敛；若挂到 Textbook，粒度又太粗。

**替代方案**：复用 `KnowledgePoint` 树——被否，用户明确不需要知识点文档，且知识点语义（考点）与教学进度（课时）不同。

### D3 用 `NetdiskAsset` 索引表，而不是每次实时扫网盘

**选择**：扫描一次落库，索引只存元数据（`fsId` / `path` / `name` / `ext` / `size` / `mtime` + 分类字段），资源访问仍走网盘实时接口。

**理由**：13k 文件实时遍历需要数分钟到数十分钟且频繁触发限流，学生端无法接受；索引表让"按章节查资源"变成一次 SQL 查询。不存文件内容，规避存储与版权风险。

**替代方案**：本地镜像——被否（276 GB + 版权 + 与"不搬文件"决策冲突）。

### D4 自动映射 + 强制人工确认，三层收敛噪音

**选择**：`mapSource ∈ {auto, manual}` + `mapConfirmed` 布尔；学生默认视图只取 `mapConfirmed=true`。收敛靠三件事：`isPinned`（每节 3-5 条）、`status=archive`（2024/2025 旧版）、`status=ignored`（广告与垃圾）。

**理由**：实测路径组织维度是出版社序列（步步高/必刷题/五三/MST），与章节无直接对应，自动映射准确率约 75%；不确认就会让学生看到错位资源。每节平均 46 个文件，不收敛则该页不可用。

**替代方案**：纯人工映射——被否，13k 条无法人工逐条处理；纯自动——被否，25% 错误率不可接受。

### D5 学生端 5 页 + 单一资源阅读器

**选择**：我的学习 / 数学章节 / 我的试卷 / 错题本 / 学习资源（+ 学习激励）。阅读器按类型分支：PDF → 流代理 iframe（支持 Range）；图片 → 分页视图；视频 → `<video>` + 流代理；doc/docx/ppt/pptx → 只给下载按钮，禁止 iframe。

**理由**：历史上 `.doc` 用 iframe 会导致 Chrome 触发下载并把页面变成 `about:blank`（已验证的坑）；统一个阅读器可避免每个页面各自实现 PDF 预览。

**替代方案**：引入 PDF.js 自绘阅读器——被否，浏览器原生阅读器已够用，且能省一个渲染层。

### D6 旧题库「保留数据 + 隐藏入口」，不删代码不删表

**选择**：`/question-bank`、`/questions` 移入「系统设置 → 高级工具」，学生端完全不可见；后端 `papers` 路由与 `Question` 表原地保留。

**理由**：题库是整卷导入链路的中间产物（拆分导入仍可能被管理员用于备课），彻底删除会连带影响 `paper-library` 的 `purpose` 区分与既有 7 份 question_source 数据；隐藏入口即可达成"学生不看题库"的目标，且可逆。

**替代方案**：删除题库模块与数据——被否，不可逆且收益低。

### D7 移除模块只下线代码路径，不删表

**选择**：难度、自动出卷、知识点文档、在线测验四类功能，删除路由注册与前端页面，表与历史数据保留。

**理由**：SQLite 删表不可回滚且伴随外键连锁；先下线路径可让 v2 快速收敛，后续确认无回滚需求再做一次性清理（v1 已有 `plan-a-debt-cleanup` 的先例）。

**替代方案**：同步删表——被否，风险高于收益。

### D8 M1 采用"原样拷贝"，禁止顺手重构

**选择**：搬壳阶段只复制 11 个模块（auth / permission / subject / student / class / netdisk / mineru / paper / answer-sheet / wrong-question / incentive / video），只改 import 路径与被删模块的引用，不重命名、不抽象、不换写法。

**理由**：这三块资产都是"踩坑踩出来的"（链式 refresh_token、Word COM、Canvas 坐标），任何"顺手优化"都会重新引入已解决的问题。先让 v2 能启动、能登录、能看试卷库，再谈结构。

**替代方案**：边搬边重构——被否，无法区分"搬错"与"重构错"。

### D9 章节字段全部可空，先兼容后收紧

**选择**：`video_resources.section_id`、`exam_papers.section_id`、`student_wrong_questions.section_id` 均为 `Int?` + `onDelete: SetNull`；索引 `netdisk_assets(netdisk_path)` 唯一。

**理由**：存量数据（284 试卷、212 视频资源、错题）没有章节信息，可空字段让 v2 可以灰度上线；`SetNull` 让删节不会误删业务数据（删除前另做引用计数校验）。

## Risks / Trade-offs

- **[自动映射 25% 错误率会让学生看到错位资源]** → 强制 `mapConfirmed`，未确认不进学生视图；映射工作台按 `series` + `assetKind` 分组，支持批量确认与批量改挂。
- **[每节平均 46 个资源导致章节页不可用]** → 精选上限 5 + 「更多资源」折叠 + 旧版归档 + 广告屏蔽四层收敛；管理端提供"本节未精选资源数"提醒。
- **[扫描 13k 文件触发网盘限流]** → 后台任务 + 断点续扫 + 目录级游标；单次失败不重试整棵树。
- **[v2 与 v1 共用数据库，v2 改表影响 v1]** → 只做加表加列，不改既有列语义；`main` 已冻结，v1 不再部署新版本。
- **[`.doc/.pptx` 无法内嵌阅读]** → 阅读器明确提供下载与提示，不尝试渲染；避免 `about:blank` 崩溃。
- **[章节轴成为事实标准后难以扩展多教材版本]** → 预留 `Textbook.edition` 与 `grade` 字段；初期只写「人教A」，扩展时不改结构只加数据。
- **[搬壳阶段误改三块核心资产]** → M1 验收标准是"能启动 + 能登录 + 能看试卷库 + 10 页可导航 + 0 死链"，不包含任何新功能；改动 diff 必须只有 import 路径。

## Migration Plan

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M0 冻结 | `main` 打 tag `v1-final`，创建 `v2` 分支 | tag 存在，v2 可构建 |
| M1 搬壳 | 原样复制 11 个模块 + 12 个页面骨架 | 启动、登录、看试卷库；10 页可导航、0 死链 |
| M2 建轴 | 4 张新表 + 人教 A 5/19/90 种子 + 章节管理页 | 章节树可查询可编辑；幂等种子 |
| M3 索引 | 网盘全量扫描 → NetdiskAsset；自动分类与自动映射；映射工作台 | 13k 条索引落库；每节可查资源；人工确认可用 |
| M4 学生可用 | 我的学习 / 章节地图 / 章节详情 / 统一阅读器 | 学生可从首页三步到达任意资源并成功打开 PDF/图片/视频 |
| M5 闭环 | 试卷挂章节 + 发布带章节 + 答题纸 + 错题挂章节 + 章节页显示薄弱 | 一章完整走通：看资源 → 做卷 → 上传答题纸 → 教师批改 → 错题回章节 |
| M6 切换 | `v2` → `main`，tag `v2.0` | v2 在 main 上可运行；v1 停止维护 |

**回滚**：M0-M4 期间 `main` 始终可运行；v2 未合入前，任何阶段都可通过放弃分支回退。M6 之后回滚依赖 `v1-final` tag + 数据库未被破坏性修改（本设计只加表加列）。

## Open Questions

- 视频是否需要「已看/未看」标记？当前只记录访问，不记录观看进度（用户已明确不打时间戳）。可在 M4 之后再决定是否加轻量标记。
- 章节映射是否引入更强的匹配（如教材目录向量化）？当前用关键词匹配 + 人工确认，效果不足时再评估。
- 学习激励（打卡/徽章）是否按章节维度扩展？当前保持现状，v2 不调整。
