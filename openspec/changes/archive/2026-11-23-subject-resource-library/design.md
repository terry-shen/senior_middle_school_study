## Context

`NetdiskAsset` 已有 `assetKind`、`audience`、`series`、`year`、`path` 等字段；`learning-service` 已有按学科识别资源的逻辑（`detectSubjectFromText`）和 `ResourceViewer` 可复用的 `AssetLite` 结构。当前 `ChapterMap` 只加载 `getVideoSeries`，资源库查询只存在于管理员端的 `netdisk-index` 接口。

数学学生可见未映射资源 5,019 条，候选章节匹配分 ≥4 的仅 371 条，因此本次不做 `sectionId` 映射，只做只读归集。

## Goals / Non-Goals

**Goals:**

- 学科页提供与视频主线并列的「教辅资源」分类
- 复用现有索引字段做系列/书目分组，不新增表和映射字段
- 支持类型、年份、关键词筛选和分页
- 首期用数学验证，接口按学科通用

**Non-Goals:**

- 不自动写 `sectionId`、不改变 `mapSource` / `mapConfirmed`
- 不做教材章节级的自动归类（候选分不足）
- 不做教师端资源库；教师专属资源不进入
- 不改造网盘扫描和映射工作台

## Decisions

### 教辅资源走 learning 接口，不复用管理员接口

学生端需要按学科、受众过滤，并且不能看到教师专属资源；`/api/netdisk-index/assets` 是管理员接口。因此在 `learning-service` 新增只读查询，返回的字段裁剪为学习端需要的 `AssetLite`。

替代方案是放宽管理员接口权限，但会把 `sectionId`、映射状态等管理字段暴露给学生，且受众过滤容易漏，因此不采用。

### 按「系列 + 书目目录」两级归集

系列优先取 `asset.series`；为空时用路径/文件名关键词补判（步步高、5.3、优化设计、必刷题、一遍过、金考卷、全品、赢在微点、天星、高考帮、衡中学案、MST、一数、真题），仍无法识别归入「其他资料」。

书目从路径目录推导：去掉 `高中学习系统`、`教辅材料`、`教辅资料`、`教辅资料合集`、`2026教辅资料` 等固定根，跳过 `Word版`、`PDF版`、`配套课件` 这类通用尾目录，优先取包含 `复习|讲义|必刷|真题|模拟|试卷|一轮|二轮|同步|教材|知识点|专题` 的目录段。

不按 `candidateSections` 归集：数学资源中 93% 的候选分低于 4，按候选分分组会把大量资源挂到错误章节。

### 汇总与文件列表分开

新增两个接口：

- `GET /api/learning/resource-library/summary?subjectId=&kind=&year=&q=` 返回总数、类型/年份分布、系列与书目分组计数
- `GET /api/learning/resource-library/assets?subjectId=&series=&book=&kind=&year=&q=&page=&limit=` 返回分页文件列表

汇总结果按学科缓存 2 分钟；文件列表始终走数据库分页，避免一次返回数千条。管理员映射后最多 2 分钟从分类消失，可接受。

### 学科可进入性计入未映射资源

`listLearningSubjects` 增加 `resourceCount`，与资源库使用同一套过滤和学科识别。`ChapterMap` 原先在 `sectionCount=0 && videoCount=0` 时直接显示「待建设」，改为三者全为 0 才待建设。

### 前端用并列标签，不混入视频树

学科页顶部增加「🎬 视频主线课程 / 📚 教辅资源」两个标签。视频标签保持现状；教辅资源标签首次点击才加载汇总，避免每次进入学科页都查询数万条资源。资源打开复用 `ResourceViewer`，`sectionId` 传 `null`。

### 映射口径改为「学习主线」

原口径只有 `sectionId` 非空才算已映射，导致教辅资源被统计成未映射。新的 `computeLearningLine` 按优先级判定：教材小节 → 视频主线 → 教辅资源线 → 未归主线；`mapped` 为前三类之和，`unmapped` 只表示未归主线。管理端统计增加 `byLine`，映射页的「未映射收件箱」改名为「未挂小节收件箱」，避免把教辅资源线误称为未映射。

## Risks / Trade-offs

- 25,600 条学生可见未映射资源，按学科内存过滤有开销 → 只查必要字段，汇总按学科缓存 2 分钟。
- 系列/书目靠规则推导，会有误分组 → 保留关键词搜索和类型/年份筛选，分组标题只作导航，不作为权威分类。
- Word/PDF 同书多版本会重复出现 → 首期接受，后续按去扩展名后的书名做去重合并。
- 资源映射后最多 2 分钟才从分类消失 → 用短 TTL 换取实现简单；不引入跨服务缓存失效。
- 数学首期验证，其他学科数据质量未逐一核对 → 接口通用但文案和默认值不改，先看数学效果。

## Migration Plan

1. 后端先发布：`resourceCount`、两个只读接口、分页与缓存。
2. 前端随后发布：学科页标签、筛选、分组与加载更多。
3. 无数据库变更；回滚只回代码，索引和映射数据不受影响。
